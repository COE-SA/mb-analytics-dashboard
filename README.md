# Munch Bakery — لوحة التحكم المالية والتشغيلية

لوحة تحكم ثابتة تعرض مؤشرات المبيعات والفروع والتطبيقات والمنتجات والربحية وطرق الدفع من بيانات Odoo. تُنشر الواجهة كملفات ثابتة، بينما يُحدَّث ملف `data.json` من خلال عملية مجدولة تحفظ لقطة بيانات قابلة للمراجعة.

> **تنبيه أمني:** لا تضع عنوان Odoo أو اسم قاعدة البيانات أو اسم المستخدم أو مفتاح API في الكود أو الملفات أو المحادثات. استخدم أسرار المستودع فقط. إذا ظهر مفتاح في سجل أو محادثة أو ملف سابق، ألغِه وأنشئ مفتاح خدمة جديداً فوراً.

## ما تعرضه اللوحة

| القسم | المحتوى | ملاحظة تفسيرية |
|---|---|---|
| النظرة العامة | بطاقات مبيعات DTD وWTD وYTD، وعدد الطلبات، ومتوسط الطلب، والإجمالي التراكمي | تستبعد البطاقات مبيعات اليوم الجاري حتى تكون المقارنة قابلة للاعتماد. |
| المقارنات والتوقعات | آخر يوم مكتمل مقابل اليوم الذي قبله، والأسبوع الماضي مقابل الأسبوع الذي قبله، والعام الماضي مقابل العام الذي قبله، وتوقعات قصيرة المدى | التوقعات تقديرية وليست ضماناً للنتائج المستقبلية. يظهر منهج التقدير وحجم العينة داخل اللوحة. |
| الفروع | الإيرادات والطلبات ومتوسط الطلب والحصة واتجاهات شهرية | تتطلب بيانات `config_id` سليمة في أوامر نقاط البيع. |
| التطبيقات | مساهمة قنوات الطلب، آخر 30 يوماً، والشهر والسنة | تعتمد على تصنيف شريك الطلب في Odoo. راجع الأسماء عندما يضاف تطبيق جديد. |
| المنتجات | أفضل المنتجات بالإيراد والكمية والتكلفة والهامش | التكلفة الحالية هي `standard_price` للمنتج؛ لا تمثل بالضرورة تكلفة تاريخية فعلية لكل طلب. |
| الربح والخسارة | إيرادات ومصروفات محاسبية شهرية وهامش محسوب | لا يُعتبر تقريراً محاسبياً نهائياً قبل اعتماد شجرة الحسابات وسياسة توزيع المصروفات. |
| طرق الدفع | مبالغ المعاملات وعددها وحصة كل وسيلة | مصدره `pos.payment` ويجب تفسيره منفصلاً عن صافي مبيعات الفواتير عند الحاجة. |
| جودة البيانات | حالة اكتمال اللقطة، عدد الأيام، ووقت آخر تحديث | لا تعتمد المقارنات عندما تظهر اللوحة تحذير جودة بيانات. |

## البنية

```text
.
├── index.html                         # واجهة الداشبورد أحادية الصفحة
├── data.json                          # آخر لقطة منشورة من البيانات
├── fetch.py                           # استخراج وتحويل بيانات Odoo
├── validate_snapshot.py               # يمنع نشر اللقطات الناقصة أو غير المطابقة
└── workflow-templates/daily-data-update.yml
                                      # قالب التحديث اليومي المراجَع
```

يقرأ `fetch.py` البيانات من Odoo باستخدام XML-RPC، ويحوّلها إلى `data.json`، ثم يتأكد `validate_snapshot.py` من اكتمال السلسلة اليومية والبنية الأساسية قبل السماح بعملية النشر الآلي.

## الإعداد الآمن

### 1. إنشاء حساب خدمة في Odoo

أنشئ حساب خدمة مخصصاً للوحة التحكم بدلاً من استعمال حساب شخصي، وامنحه صلاحية قراءة فقط لأقل النماذج المطلوبة. ابدأ بنماذج المبيعات ونقاط البيع والمنتجات والمخزون والمحاسبة والمشتريات، ثم قلّص الصلاحيات إلى الحد الأدنى بعد التحقق من الاستعلامات. استخدم مفتاح API جديداً لم يسبق مشاركته في أي مكان.

### 2. إضافة أسرار المستودع

من صفحة المستودع، انتقل إلى **Settings → Secrets and variables → Actions**، ثم أضف الأسرار الأربعة التالية. لا تضع أي قيم في `README.md` أو `fetch.py` أو ملفات البيئة التي قد تُرفع إلى Git.

| اسم السر | الغرض |
|---|---|
| `ODOO_URL` | عنوان خادم Odoo من دون بيانات اعتماد مضمنة في الرابط. |
| `ODOO_DB` | اسم قاعدة البيانات. |
| `ODOO_USER` | اسم مستخدم حساب الخدمة. |
| `ODOO_API_KEY` | مفتاح API الجديد لحساب الخدمة. |

بعد إضافة الأسرار، فعّل صلاحية سير العمل في **Settings → Actions → General → Workflow permissions** بحيث يستطيع التحديث اليومي كتابة `data.json` في المستودع. لا تشارك قيم الأسرار داخل المحادثة.

### 3. تفعيل قالب التحديث اليومي

لأن بعض حسابات التكامل لا تملك صلاحية إضافة أو تعديل ملفات `.github/workflows`، يوجد القالب المراجَع في `workflow-templates/daily-data-update.yml`. انسخه من واجهة GitHub إلى المسار `.github/workflows/daily-data-update.yml` ثم أضفه في طلب دمج، أو امنح تكامل التطوير صلاحية **Workflows** ليتم وضعه تلقائياً. لا تنسَ مراجعة السطر المجدول؛ فهو مضبوط على الساعة 06:00 بتوقيت السعودية.

### 4. تجربة أول تحديث يدوي

بعد إضافة ملف التشغيل، افتح تبويب **Actions**، ثم اختر **Daily dashboard data update** واضغط **Run workflow** على فرع `master`. ستتوقف العملية بأمان إذا كانت الأسرار غير مكتملة أو إذا كانت اللقطة الناتجة لا تحقق فحوص الجودة. عند نجاح العملية، يُسجّل تحديث لملف `data.json` فقط.

### 5. تفعيل النشر الثابت

من **Settings → Pages**، انشر من الفرع الذي تعتمدونه للإنتاج ومن جذر المستودع. بعد التحقق من النسخة الجديدة عبر طلب دمج، ادمجها في `master` ثم تأكد من ظهور وقت التحديث في رأس الداشبورد.

## قواعد البيانات والمقارنات

تعتمد حدود اليوم على **Asia/Riyadh (UTC+3)**، مع تحويل طوابع Odoo الزمنية من UTC إلى توقيت السعودية قبل حساب اليوم أو الساعة. تستخدم لوحة المقارنات الفترات التالية:

| المؤشر | فترة العرض | الفترة المرجعية |
|---|---|---|
| DTD | آخر يوم مكتمل | اليوم الذي قبله |
| WTD | من بداية أسبوع الأحد حتى آخر يوم مكتمل | نفس عدد الأيام من الأسبوع السابق |
| YTD | من بداية السنة حتى آخر يوم مكتمل | الفترة المناظرة من العام السابق |
| مقارنة الأسبوع | الأسبوع الماضي الكامل من الأحد إلى السبت | الأسبوع الكامل الذي قبله |
| مقارنة السنة | العام الميلادي السابق الكامل | العام الذي قبله |
| الشهر | من بداية الشهر حتى اليوم | نفس عدد الأيام من الشهر السابق، ثم الفترة المطابقة من العام السابق |
| توقع الغد | أيام مكتملة حديثة، ويفضل الأيام المطابقة في الأسبوع | يعرض حجم العينة والمنهج داخل اللوحة |
| توقع الشهر أو السنة | معدل الأيام المكتملة فقط | لا يصدر إذا لم تتوفر عينة دنيا |

## تشغيل محلي آمن

لا تستخدم بيانات اعتماد إنتاجية في ملف محلي أو في سجل طرفية قابل للمشاركة. عند وجود متغيرات البيئة في جهاز آمن، يمكن توليد اللقطة ثم التحقق منها كما يلي:

```bash
python -m unittest -v test_fetch.py
python fetch.py
python validate_snapshot.py data.json
```

يجب أن يمر الاختبار والتحقق قبل رفع `data.json`. يفشل التحقق إذا كانت بنية البيانات أقدم من الإصدار 6، أو كانت السلسلة اليومية أقصر من الحد الأدنى المطلوب، أو كانت حالة جودة البيانات غير سليمة.

## قائمة التشغيل قبل النشر

| البند | الحالة المطلوبة |
|---|---|
| الأمن | تم تدوير أي مفتاح ظهر سابقاً، ولا توجد أسرار داخل الملفات المتتبعة. |
| البيانات | تحديث يدوي ناجح، ونجاح `validate_snapshot.py`. |
| المقاييس | تمت مطابقة عينة من المبيعات والطلبات مع Odoo. |
| الواجهة | تم اختبار النظرة العامة والمقارنات والفروع والتطبيقات والمنتجات والربحية وطرق الدفع والتاريخ على سطح المكتب والجوال. |
| النشر | نُفذت التغييرات عبر فرع وطلب دمج، ثم تم التحقق من النسخة المنشورة. |

## حدود يجب اعتمادها مع الإدارة والمالية

تُظهر اللوحة مؤشرات تشغيلية مفيدة، لكن دقة تقرير الربح والخسارة تعتمد على تعريفات العمل. قبل اعتماد الأرقام لاتخاذ قرار مالي، وثّق ما إذا كان الإيراد قبل أو بعد الخصومات والضرائب والمرتجعات، وكيف تُحسب عمولات التطبيقات، وما إذا كانت الرواتب والإيجار والمصروفات المشتركة موزعة على الفروع، وكيف تُحسب تكلفة البضاعة المباعة تاريخياً.

## الصيانة

عند إضافة فرع أو تطبيق أو طريقة دفع جديدة، راجع تصنيفها في Odoo ثم تحقق من ظهورها في اللقطة الجديدة. وعند فشل التحديث، ابدأ بسجل عملية التحديث في GitHub Actions، وتحقق من صلاحية حساب الخدمة والأسرار، ثم أعد تشغيل العملية يدوياً بعد معالجة السبب.
